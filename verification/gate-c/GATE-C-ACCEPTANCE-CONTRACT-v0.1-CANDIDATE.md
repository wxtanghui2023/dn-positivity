## §1 验收范围与边界

### 1.1 五个验收域

| 编号 | 验收域 | 核心问题 |
|---|---|---|
| C1 | 执行路径完整性 | 正式入口是否使用指定的共享 r2 判分器？是否存在评分旁路？ |
| C2 | 判分与失败关闭 | 异常响应、缺失依赖、终止状态等是否按规范处理？ |
| C3 | 预注册语义一致性 | Markdown、JSON 与实际执行行为是否遵守同一组关键约束？ |
| C4 | 发布与证据完整性 | 被测代码、版本标识、哈希清单、测试结果是否指向同一固定版本？ |
| C5 | 契约与元数据一致性 | 文档中的版本、数量、路径、声明是否与实际内容一致？ |

**声明**：C1–C5 是**本次提出的候选规范**，**不是** r2 早已存在的正式标准；正式生效前须经有权审查方确认并冻结。

### 1.2 逐项通过条件

**状态定义**：`PASS` = 有充分证据满足条件；`FAIL` = 有可复现反例；`BLOCKED` = 证据不足或环境不满足；`N/A` = 经批准确认不适用；`INCONCLUSIVE` = 执行了但结果无法区分符合与不符合。

#### C1 — 执行路径完整性
- **通过条件**：① 正式 CLI 入口与测试入口最终调用**同一**评分路径；② 共享判分器函数绑定符合预期，**必要的对象同一性断言通过**；③ 不存在可影响正式结果的**旧版评分旁路**。
- **证据要求**：固定版本源码、调用链、**对象同一性测试**、**旁路搜索结果**。
- **失败条件**：正式路径调用旧判分器 / 测试与正式走不同评分逻辑 / 存在未受控的有效旁路。

#### C2 — 判分与失败关闭
- **通过条件**：① 非法、截断、格式错误、缺字段响应均按预注册语义分类；② **终止状态优先级**与 `MODEL_NONCOMPLIANCE` 计数语义正确；③ 必需依赖缺失时**明确失败，不静默跳过**；④ 未获授权时**模型调用被阻止**。
- **证据要求**：正常 / 边界 / 异常案例 + **失败关闭负控**的逐项结果。
- **失败条件**：非法响应被错误计分 / 失败被吞掉 / 拒绝样本被错误排除 / 未经授权调用可执行。

#### C3 — 预注册语义一致性
- **通过条件**：① Markdown 与 JSON 对**禁止复判、禁止覆盖、no-core 语义、终止状态优先级、聚合规则、字段语义**的规定一致；② 执行代码未违背上述约束；③ 第一轮历史材料**仅按授权的完整性用途**使用，**不被用作能力证据**。
- **证据要求**：**条款对照表**、对应字段、代码引用、必要的行为测试。
- **失败条件**：任一关键约束缺失 / 冲突 / 执行时被绕过。

#### C4 — 发布与证据完整性
- **通过条件**：① 明确**唯一的被测提交**或不可变归档；② 哈希清单覆盖范围明确，实际计算值一致；③ 测试日志能对应到该版本与实际执行结果；④ 第三方报告明确区分**已测 / 未测 / 证据来源**。
- **失败条件**：文件哈希不符 / 测试版本无法确定 / 报告与执行产物不匹配 / 结果无法追溯。

#### C5 — 契约与元数据一致性
- **通过条件**：① 声明的**文件数、哈希条目数、版本标识**与实际内容一致；② **可派生信息由数据源生成或自动校验**，而非由互不相关的手填常量维护；③ 文档修订版本与发布包版本**能明确区分**。
- **失败条件**：文档存在**错误的关键元数据**，或**自动化声称与实际机制不符**。

### 1.3 现有证据初步映射（**非最终签署**）

| 验收域 | 当前初步状态 | 剩余事项 |

## §2 验收流程与测试规范

### 2.1 六阶段流程（G0–G5）

| 阶段 | 名称 | 输入 → 输出 | 停止条件 |
|---|---|---|---|
| G0 | **冻结验收契约** | 本草案 → 经授权的标准版本、范围、必需项与例外规则 | 标准未批准 / 版本不明确 / 通过条件不可判定 |
| G1 | **锁定被测版本与证据** | — → Git commit、文件清单、SHA-256、第三方报告、测试日志及**每项证据来源** | 证据无法关联到同一固定版本 |
| G2 | **证据映射与差距分析** | — → 每项 PASS/FAIL/BLOCKED/N/A + 证据引用（**先复用充分证据，不重跑已通过测试**） | — |
| G3 | **执行缺口测试** | 仅针对证据不足 / 发现缺陷 / 代码修订影响项 | 关键失败 / 未经授权副作用 / 测试环境失去可信性 |
| G4 | **独立复核与统一裁定** | — → 逐项裁定、例外清单、整体 Gate C 状态 | **不得用汇总 PASS 替代单项证据** |
| G5 | **归档并决定下一阶段** | 归档契约版本、证据索引、测试结果、修复记录、签署结果 | 未满足整体判定规则不得进入后续阶段 |

### 2.2 测试登记字段（每测试必填）

| 字段 | 要求 |
|---|---|
| `test_id` | 稳定且唯一 |
| `contract_clause` | 对应条款，如 `C2.3` |
| `artifact_commit` | 实际被测的固定提交 |
| `preconditions` | 环境、依赖、权限、输入前提 |
| `test_method` | 可复现命令 / 代码审查方法 / 对照步骤 |
| `expected_result` | **事先规定**的准确结果 |
| `actual_result` | 实际观察，**不得事后改写预期** |
| `evidence_ref` | 日志、输出、源码位置、哈希记录 |
| `verdict` | PASS / FAIL / BLOCKED / N/A |
| `reviewer` | 执行者及复核者 |

### 2.3 冻结规则（六条禁令）

1. **禁止事后改标准**：测试失败后可改实现，但**不得**为通过而倒改原验收条件；标准变更须走**独立版本变更流程**。
2. **禁止静默跳过**：必需依赖 / 测试 / 断言缺失时，**不得**将整体结果记为 PASS。
3. **禁止无依据重跑**：已通过测试在代码与相关依赖未变时**复用证据**；修改后仅重跑受影响测试及必要回归。
4. **禁止把失败改成不可评分来消除失败**：`NONCOMPLIANCE`、终止状态、缺字段、无效响应必须依既定语义计入结果。
5. **禁止越权调用模型**：本次 Gate C 工程验收**不需要**模型调用；**调用保持为零**，除非另有明确授权。
6. **独立记录未测试项**：外部锚点逐字节比对、网络抓包等未执行项**如实记录**——不得自动当作通过，也不得在无契约依据时自动当作失败。

## §3 结果处理与决策

### 3.1 单项结果语义与动作

| 结果 | 含义 | 必须动作 | 可进入下一阶段？ |
|---|---|---|---|
| `PASS` | 条款已被充分证据支持 | 归档证据，不重复测试 | 可以（前提：其他必需项满足） |
| `FAIL` | 已发现违反验收条件的反例 | 登记缺陷、定位原因、修复后定向测试 + 回归 | **不可以**越过受影响门禁 |
| `BLOCKED` | 无法得出可靠结论 | 明确缺失的证据/权限/环境，解除阻塞后继续 | 不可以宣称整体通过 |
| `N/A` | 经授权确认不适用 | 记录理由及批准者 | 仅当契约允许且批准有效 |
| `INCONCLUSIVE` | 执行了但无法区分 | 改进测量或测试方法，保持未决 | 不可以 |

> **`BLOCKED` ≠ `FAIL`**：前者**无法判定**，后者**已证明不符合**；两者**均不得**作为整体 PASS 依据。

### 3.2 缺陷严重度与升级

| 级别 | 定义 | 动作 |
|---|---|---|
| **Critical** | 评分逻辑可被绕过 / 未授权模型调用可执行 / 历史材料被用于禁止的复判或能力证明 / 结果完整性无法保障 | **立即停止验收**；修复后**重新审查所有受影响条款** |
| **Major** | 关键语义不一致 / 必需依赖未失败关闭 / 关键测试覆盖缺失 / 发布版本无法确认 | **阻止 Gate C 通过**；修复后定向测试 + 必要回归 |
| **Minor** | 不改变执行语义与证据有效性的文档/命名问题 | 按契约记录、限期修复；**是否阻塞须事先明确**，不得由执行者临时决定 |

> **D-⑦ 的严重度不得仅凭「改起来容易」决定**。若数量错误**影响审计完整性**或暴露**未实现的机械生成声明**，至少须**正式登记并验证修复**；是否阻塞由**冻结后的契约**决定。

### 3.3 整体决策表

| 条件 | 裁定 |
|---|---|
| **契约未批准** | **不作正式裁定**（当前状态） |
| 契约已批准 + 任一必需项 `FAIL` | **整体 FAIL** |
| 契约已批准 + 有未决项（`BLOCKED`/`INCONCLUSIVE`） | **阻止通过** |
| 契约已批准 + 全部必需项 `PASS` | 进入**签署** |

### 3.4 Gate C ⟂ 预注册批准（**两个独立决策**）

| 情形 | 结论 |
|---|---|
| Gate C PASS，但容量标定/预算冻结/k 固定未完成 | **Gate C PASS，预注册仍 NOT APPROVED** |
| Gate C FAIL | 修复缺陷；**不得**用预注册批准条件掩盖工程失败 |
| Gate C BLOCKED | 只解决阻塞证据；**不得**把不确定性写成失败或通过 |
| Gate C 与预注册批准**均**通过 | 仅代表**获准按预注册方案开展后续工作**；**仍不证明**框架具备自主数学发现能力 |

## §4 执行决定（本次项目）

1. **冻结本验收规范候选版**，提交授权审查（**不得**冒充 r2 原有标准）。
2. **保留已通过的 r2 工程验证证据**，不重跑无必要的测试。
3. **处理 D-⑦**：生成**新修订版**并增加**数量生成 + 负控测试**（**不得静默改写已冻结 r2**；r2 第三方结果仍有效，但**不能**当作新版本已修复的证据）。
4. **标准获批后**，映射现有证据并执行**缺口测试**（仅针对未被现有证据覆盖的条款）。
5. **输出正式裁定记录**：每项结果、证据引用、未决问题、例外批准、签署者。
6. **另行审查预注册批准条件**；**不得**将 Gate C 结论当作这些条件已满足的证明。
