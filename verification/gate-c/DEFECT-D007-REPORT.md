# D-⑦ 缺陷报告：文档数量声明与实际 JSON 不符

> 状态：**已复现（FAIL）**｜严重度：**提议 Major（是否阻塞由冻结后的契约决定）**｜0 模型调用
> 关联包：`verification/a1-v1.2-prereg-r2`（**不改动**；修复见新修订版 `verification/a1-v1.2-prereg-r3`）

## 一、实测事实（可复现）

| 声明处 / 载体 | 值 |
|---|---|
| `A1-v1.2-PREREGISTRATION-DRAFT-r2.md`「哈希（**26** 项，机械计算）」（×2 处） | **26** |
| JSON `artefact_hashes` **实际键数** | **22** |
| `SHA256SUMS.txt` 条目数 | **23** |
| 包内文件总数 | **24** |
| `DEFECT-REPAIR-REGISTER.md` 中的数量声明 | 15、**26**、15 |

**复现命令**
```bash
cd verification/a1-v1.2-prereg-r2
grep -n '项' A1-v1.2-PREREGISTRATION-DRAFT-r2.md
python3 -c "import json;print(len(json.load(open('A1-v1.2-PREREGISTRATION-DRAFT-r2.json'))['artefact_hashes']))"
wc -l SHA256SUMS.txt
```

## 二、根因（已定位到代码行）

- `build_publish_r2.py:237`：`n_hash = len(files)` —— 以**构建当时的全量文件列表**计数（= **26**），并据此在 MD 中注入「%d 项」（`:122`、`:253`、`:256`、`:277`）。
- 而 JSON 的 `artefact_hashes` 覆盖的是**较窄集合**：根目录文件，**排除** `SHA256SUMS.txt` 与 JSON 自身（**= 22**，且 deps/ 与 ROUND1-ARCHIVE/ 另计）。
- 其后 `repair_r2b/r2c/r2d` **只重生成 JSON**，**MD 常量从未重生成** ⟹ **两个互不相干的数量源发生漂移**。

> **性质**：这不是"写错一个数字"，而是**"机械注入"的实现与声明不符**——即 §1.2-C5② 所指的
> 「可派生信息由**互不相关的手填常量**维护」，以及 §1.2-C5 失败条件中的「**自动化声称与实际机制不符**」。
