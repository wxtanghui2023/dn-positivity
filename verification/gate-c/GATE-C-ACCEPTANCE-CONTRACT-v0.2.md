## §1 验收标准细则

Gate C 分**五个验收域**，每项**预先**确定：通过条件、失败条件、证据要求、责任人。

| 编号 | 验收域 | 必须满足的条件 | 责任人 |
|---|---|---|---|
| **C1** | 执行路径完整性 | 正式运行器调用**共享 r2 判分器**；测试与正式路径**一致**；**不存在有效评分旁路** | 执行者（甲）；复核者独立 |
| **C2** | 判分与失败关闭 | 异常输入、终止状态、缺失依赖、**未授权模型调用**均按**预定语义**处理 | 执行者；复核者独立 |
| **C3** | 预注册一致性 | Markdown、JSON、执行代码在**禁止复判、no-core、聚合规则、字段语义**上一致 | 执行者；复核者独立 |
| **C4** | 发布与证据完整性 | **固定版本**、文件哈希、测试日志、第三方报告**相互对应** | 执行者；第三方复核 |
| **C5** | 元数据与契约一致性 | **文件数量、哈希条目数量、版本标识、文档声明**与实际内容一致 | 执行者；复核者独立 |

### 1.1 状态语汇（统一）

`PASS` ｜ `FAIL` ｜ `BLOCKED` ｜ `INCONCLUSIVE` ｜ **经批准的** `N/A`

- `BLOCKED` = **无法判定**；`FAIL` = **已证明不符合**。二者**均不得**作为整体 PASS 依据。
- `N/A` **仅在契约允许且批准有效**时可排除该项。

### 1.2 已知问题 D-⑦（已登记）

| 项 | 事实 |
|---|---|
| 症状 | MD 声明 **26 项**哈希，JSON `artefact_hashes` **实际 22 项**（`SHA256SUMS.txt` 23 条；文件 24 个） |
| 已核对 | **22 项哈希值本身全部正确**（第三方与本地均复核） |
| 缺陷性质 | **数量声明不正确**；根因 = **两个互不相干的数量源**（构建期 `len(files)` 常量 vs 后续重生成的窄集合） |
| 处置要求 | 须由**自动生成或自动一致性检查**修复；**不得**手工改数字后即宣布机制已修复 |
| 修复状态 | 已出**新修订版 r3**（r2 逐字节未动）：单源计数 + 入包校验器 + **负控**（见证据报告 T-05/T-06） |

## §2 验收流程与测试规范（严格顺序）

| # | 阶段 | 要点 |
|---|---|---|
| 1 | **冻结标准** | 审查方批准契约，锁定**版本、必需项、失败条件、例外规则** |
| 2 | **锁定证据** | 记录被测 **Git commit**、哈希清单、第三方报告、测试日志 |
| 3 | **逐项映射** | 证据对应 C1–C5；**已充分验证者不重复测试** |
| 4 | **执行缺口测试** | **仅**测证据不足或代码修改影响项；每项**预先**写明输入、预期结果、判定方法 |
| 5 | **独立复核** | 检查测试是否**真正覆盖**条款；确认**失败未被静默跳过** |
| 6 | **正式裁定与归档** | 保存逐项结论、证据引用、未决事项、签署记录 |

### 2.1 每项测试必录字段

`test_id` ｜ 验收条款 ｜ 被测版本 ｜ 前置条件 ｜ 测试方法 ｜ **预期结果（事先）** ｜ 实际结果 ｜ 证据位置 ｜ 最终状态

### 2.2 冻结禁令

1. **禁止事后改验收标准迎合结果**；标准确需修改 ⟹ **单独记录变更理由、版本、批准者**。
2. **禁止静默跳过**必需依赖/测试/断言。
3. **禁止无依据重跑**（代码与依赖未变则复用证据）。
4. **禁止把失败改判为不可评分**以消除失败。
5. **禁止越权模型调用**（本次工程验收 **0 调用**）。
6. **未测试项独立登记**：不自动判通过，也不自动判失败。

## §3 结果→后续流程

| 结果 | 后续动作 | 允许 Gate C 通过？ |
|---|---|---|
| `PASS` | 归档证据，继续检查其他必需项 | **仅当全部必需项通过** |
| `FAIL` | 登记缺陷、修复、**定向复测 + 必要回归** | **否** |
| `BLOCKED` | 补足证据/权限/环境，**再重新裁定** | **否** |
| `INCONCLUSIVE` | 改进测试方法，**保持未决** | **否** |
| `N/A` | 记录理由并取得契约要求的批准 | **仅在获准后排除** |

**整体规则**：**任何必需项 FAIL ⟹ 整体不通过**；**任何必需项未决 ⟹ 整体不通过**。
**非阻塞缺陷、例外及其批准方式必须在本标准冻结前明确**，**不得临时决定**。

### 3.1 Gate C 与预注册批准（**两个独立决策**）

| 情形 | 结论 |
|---|---|
| Gate C 通过 | **不代表**预注册自动获批 |
| Gate C 失败 | **不得**由预注册状态替代或掩盖 |
| 二者均通过 | **仍不构成**自主数学发现能力的证明 |

**预注册批准条件（另行检查）**：容量标定、预算冻结、`k` 固定等。
