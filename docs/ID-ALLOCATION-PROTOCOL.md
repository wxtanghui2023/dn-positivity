## §0 风险（为什么必须机制化）

```
⚠️ 撞车的真实危害**不是**"名字难看"，而是**越界改写他人成果** ✓：
   · 一路以为 `docs/E130-*.md` 是自己的 ⟹ 追加载重【勘误】/ 重命名 / 批量 sed ⟹ **覆盖或污染他路内容** ✗
   · `git add` 用通配 ⟹ 把他路**在制品**（untracked）一起提交 / 或 `git mv` 误改他路文件 ✗
   · 交叉引用失效（他路文档指向同号但不同物的档）✗
⟹ 结论 ✓：**必须"先领号后建文件"**，且**任何批量操作前先跑检查器** ✓
```

## §1 三条硬规则

```
【规则 1 · 先领后建 ✓】新建任何 `E###-` 档/**`E###_` 脚本**前，先领号：
     $ scripts/id_claim.sh <stream> <slug>      # 输出一行 "E###"（原子占位 ✓）
   领到号**之后**才创建文件 ✓；**禁止**自行猜号/沿用旧号 ✗
【规则 2 · 分号段 ✓】每个工作流**只能在自己号段内领号**：
     · main  = **E###**（主线工作流：E100–E13x 零和/渐近律线等 ✓）
     · audit = **V###**（本会话：小灵 —— 审计/核验/裁决线 ✓，已用 V101–V107 ✓）
     · spare = **其它字母前缀**（如 `Z###`；需要时**先登记** ✓）
   ⚠️ **为何不用 E3xx**：项目已有 `E30/E32/E36/E39/E39b` ⟹ `docs/E30*` 通配会**误命中 E301+** ✗
      （＝"覆盖不该覆盖"的真实入口）⟹ 迁移改用 **V 系列**：`V*` 与现有 E/p/B/R/A/ALIGN 等**前缀零重叠** ✓
   非本体系命名（`gate<n>-`／`R-A1-`／`ALIGN-*`／`p<n>-`／`B<n>-`／`MASTER-*`／`HOT-STATE` 等）**不受本约** ✓
【规则 3 · 提交前自检 ✓】任何提交**前**跑：
     $ python3 scripts/check_ids.py     # 期望 exit 0（无同号多文件 ✓）
```

## §2 台账与原子性

```
· 台账 ✓ `docs/ID-CLAIMS.tsv`（列：ID｜stream｜slug｜时间 ✓）—— **唯一权威** ✓
· 原子占位 ✓ `docs/.idclaims/E###.lock/`（`mkdir` 原子 ⟹ 并发下不会双领 ✓）
· 占用判定 ✓ ① 锁存在 ② `docs/E###-*` 存在 ③ `scripts/E###_*` 或 `E###-*` 存在 ⟹ 任一即跳过 ✓
```

## §3 撞车响应（发现撞车时）

```
① **后到者改号** ✓（不改先到者 ✓）；② 改号**必须以【勘误】留档**（T10 ✓）并写映射 ✓；
③ **严禁**：对非本流文件追加载重/改名/注入内容 ✗；④ 若产权不明 ⟹ **停手并上报** ✓（不猜 ✓）；
⑤ 批量操作（`git add`／`git mv`／`sed -i`／重命名）**一律显式路径**，禁通配 ✗
```
